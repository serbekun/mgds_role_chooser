# MGDS Role Chooser

[English](README.md) | Русский

Discord-бот на Rust, который публикует в канале панель с кнопками для самостоятельной выдачи и снятия игровых ролей на сервере Maxim Games Discord Server.

Панель выглядит как сообщение **«Выберите себе роль:»** с кнопками (по 5 в ряд). Нажатие на кнопку выдаёт роль, повторное нажатие — снимает её. Ответ на нажатие виден только нажавшему (ephemeral), а состояние ролей при перезапуске бота не теряется: кнопки работают за счёт статичных `custom_id`, а не хранения сообщений в памяти.

## Возможности

- Панель с кнопками для выдачи/снятия ролей.
- Переключение роли по повторному нажатию.
- Эфемерные ответы с результатом операции.
- Логирование через `tracing`.
- Роли и каналы публикации задаются вместе в `config.yaml`, поэтому их можно менять без пересборки бота.

## Требования

- Rust 1.85+ (проект использует edition 2024).
- Discord-приложение с ботом и его токен.

## Настройка Discord

1. Создайте приложение на [Discord Developer Portal](https://discord.com/developers/applications).
2. На вкладке **Bot** получите токен.
3. Привилегированные intents (Server Members, Message Content) не требуются — бот использует только `GUILDS`.
4. Пригласите бота на сервер со scope `bot` и правами:
   - **Manage Roles** — для выдачи и снятия ролей;
   - **View Channels** и **Send Messages** — для публикации панели в целевом канале.
5. Роль бота должна находиться **выше** всех ролей, которыми он управляет. Иначе Discord вернёт ошибку при попытке выдать роль.

## Конфигурация

Бот настраивается через переменные окружения:

| Переменная | Обязательна | Описание |
| --- | --- | --- |
| `MGDS_ROLE_CHOOSER_TOKEN` | Да | Токен Discord-бота. Не коммитьте его в репозиторий. |
| `MGDS_ROLE_CHOOSER_CONFIG_PATH` | Нет | Путь к YAML-конфигу ролей и каналов. По умолчанию `config.yaml`. |

Если `panel_channel_ids` пуст или не указан, бот запускается и ждёт нажатий на уже существующие кнопки. Если `MGDS_ROLE_CHOOSER_CONFIG_PATH` не задан, бот читает `config.yaml` из текущей рабочей директории.

> **Важно:** панель отправляется в каждый указанный канал при **каждом** запуске. Чтобы не плодить дубликаты, очистите `panel_channel_ids` после публикации. При ошибке отправки рассылка останавливается на этом канале, но бот продолжает запуск.

## Запуск

```bash
export MGDS_ROLE_CHOOSER_TOKEN="ваш_токен"
# Необязательно: по умолчанию используется ./config.yaml
export MGDS_ROLE_CHOOSER_CONFIG_PATH="config.yaml"

cargo run --release
```

Сборка без запуска:

```bash
cargo build --release
```

Готовый бинарник появится в `target/release/mgds_role_choosier`.

## Добавление и изменение ролей

Роли и каналы задаются в `config.yaml`:

```yaml
panel_channel_ids:
  - 123456789012345678
  - 234567890123456789

roles:
  - label: Minecraft                  # подпись на кнопке
    custom_id: role_minecraft         # уникальный ID кнопки
    role_id: 1073194781984952431      # ID роли на сервере
```

Чтобы добавить роль:

1. Добавьте новый элемент в список `roles` в `config.yaml` (например, `label: Factorio`, `custom_id: role_factorio`, `role_id: <id>`).
2. Убедитесь, что `custom_id` уникален и больше нигде не используется.
3. Перезапустите бота — пересборка не требуется.
4. Добавьте нужные ID в `panel_channel_ids` и перезапустите бота, чтобы отправить новые панели. Старые сообщения не обновятся автоматически.

Бот проверяет конфиг при старте и не запускается, если:

- список ролей пуст или содержит больше 25 ролей (ограничение Discord на одно сообщение);
- `custom_id` пустой или повторяется;
- `label` пустой или длиннее 80 символов;
- `role_id` равен `0`.

Обратите внимание: если удалить роль из `config.yaml`, кнопка с её `custom_id` в старом сообщении перестанет обрабатываться. Если изменить `custom_id`, старые кнопки перестанут работать, поэтому проще оставлять `custom_id` стабильными.

## Структура проекта

```
src/
├── main.rs      # запуск, чтение конфигурации, отправка панели при старте
├── handler.rs   # обработка нажатий на кнопки и переключение ролей
└── roles.rs     # загрузка/проверка ролей и сборка панели с кнопками
config.yaml      # конфигурация ролей и каналов публикации
```

## Логи

Бот пишет логи в stdout на уровне `INFO`. Ошибки Discord API (нехватка прав, неудачная выдача роли и т.п.) логируются через `tracing::error!`, а пользователю приходит понятное сообщение в ответе на нажатие.
